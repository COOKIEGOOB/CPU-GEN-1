# ECC, scrubbing and repair

A 96 MiB cache is a large soft-error target and a large yield risk. This
design treats both as first-class: every stored bit is covered by ECC, every
line is periodically scrubbed, and every array has spare rows, spare columns
and a fuse-backed repair path.

## 1. Codes

All codes are **Hsiao SECDED** generated by `gen/vc3d_gen_ecc.py`, which proves
the SEC/DED properties by exhaustive self-test before writing the RTL.

| protected object | code | check bits | overhead |
|---|---|---|---|
| 32-bit tag entry | SECDED(32,7) | 7 | 21.9 % |
| 64-bit metadata | SECDED(64,8) | 8 | 12.5 % |
| 128-bit line quarter | SECDED(128,9) | 9 | 7.0 % |
| 256-bit block | SECDED(256,10) | 10 | 3.9 % |
| 512-bit block | SECDED(512,11) | 11 | 2.1 % |

The line codec uses **four independent SECDED(128,9) words**, not one
SECDED(512,11). It costs 36 check bits instead of 11, and it buys two things
that matter more than the bits: four independently correctable errors per line,
and immunity to a stuck bond lane (which hits one bit in each word).

Stored word layout (144 b):

```
 [127:0]   data
 [136:128] check
 [137]     poison
 [141:138] written-nibble mask
 [143:142] sequence
```

Hsiao r=6 gives only 26 usable odd-weight columns, so 32-bit data needs r=7.
That is not an inefficiency to optimise away -- it is the constraint.

## 2. Pipelined decode

`rtl/ecc/vc3d_ecc_line_dec_pipe.v` splits the decoder at a register:
syndrome XOR trees in one cycle, the 1-of-128 correction compare in the next.
The flat decoder is 379 ps and does not fit a 333 ps cycle; splitting it is
what keeps the whole cache at 3.0 GHz instead of 2.6 GHz. The generator emits
the split pair (`vc3d_secded_syn_W`, `vc3d_secded_cor_W`) from the same
matrix as the flat codec, so they cannot drift apart, and
`tb/tb_vc3d_ecc.sv` checks them against each other.

## 3. Scrubbing

A background scrubber walks the cache reading and rewriting lines, so that
single-bit errors are corrected before a second one lands on the same word.

| | |
|---|---|
| period | one burst every 4096 cycles (programmable) |
| burst | 4 lines |
| stride | 4097 sets |
| full sweep | 32768 x 16 lines in < 1 s at 3 GHz |

The stride is 4097, not 4096: a stride sharing a factor with the set count only
visits part of the cache. The Python model checks that 4097 covers all 32768
sets and that 4096 does not -- an easy bug to ship and a hard one to find.

Scrub reads use the same ECC path as demand reads; a CE increments a per-line
counter, and a line that exceeds the threshold escalates to the repair
controller as a runtime repair request.

## 4. Redundancy

| resource | per subarray | per dielet |
|---|---|---|
| spare rows | 4 | 2048 |
| spare columns | 4 | 2048 |
| spare bond lanes | -- | 64 (8 per channel) |

Column repair is shifted-column redundancy: columns to the right of a defect
shift by one, so the repair costs one spare and no address translation. The
four quadrant macros of a row block are ganged (shared wordline drivers), so
one repair entry repairs all four -- which is also why they are placed adjacent
in `pd/scripts/floorplan_cache.tcl`.

## 5. Repair flow

```
tester:            power-on:
  MBIST march        eFuse autoload (CRC checked)
  collect fails      rebuild repair map
  allocate spares    program the dielet repair fabric
  burn eFuse         bond link training + lane repair
  verify (MBIST)     MBIST smoke test
  ...................................................
  if unrepairable -> way_disable / bank_disable, cache runs smaller
```

`rtl/repair/vc3d_repair_ctrl.v` sequences this; `tb/tb_vc3d_repair.sv` runs the
whole flow against a memory model with **injected defects** (a dead row, a dead
column, a stuck bit), burns fuses, power cycles, autoloads, and requires that
the same defective die then passes MBIST with no capacity lost.

## 6. Error reporting

| class | source | action |
|---|---|---|
| CE | base data, stacked data, tag, link | corrected, counted, logged |
| UE | base data, stacked data | poisoned response, line invalidated, IRQ |
| tag UE | tag array | forced miss, line re-fetched |
| link CRC | bond | replay; escalates to retrain, then to way retirement |
| fuse CRC | eFuse image | autoload rejected, cache boots unrepaired |

Everything lands in the CSR error log with class, source, address, way,
syndrome and dirty state -- enough for a machine-check handler to decide
whether the error is recoverable.

## 7. Yield

With D0 = 0.07 defects/cm2 on a 10.57 mm2 dielet the raw Poisson yield is
99.26 %. Modelling multi-row cluster defects (the residual the repair scheme
cannot cover) as 8 % of defects gives **99.94 % post-repair**. See
`pd/sram/sram_compiler_selection.md`.
